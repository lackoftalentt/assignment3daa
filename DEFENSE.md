## 3. Graph: как устроены данные

Файл `Graph.java`. `head[v]` хранит первую дугу списка смежности вершины. По `arcNext[a]` переходим к следующей дуге, а `arcTo[a]` даёт соседнюю вершину. Значение -1 означает конец списка. `arcEdge[a]` связывает дугу с исходным ребром, где лежат `from`, `to`, `weight`.

Для directed ребра u→v создаётся одна дуга. Для undirected u—v создаются u→v и v→u, но идентификатор исходного ребра один. Поэтому Kruskal сортирует E исходных рёбер, а Prim может просмотреть 2E дуг. Списки вставляются в начало, поэтому порядок соседей обратен порядку добавления; это может менять конкретный обход и maxDepth, но не вес MST или состав SCC.

Массивы — компактная реализация adjacency list: здесь не нужна матрица V×V и не нужны миллионы Java-объектов. Пространство графа O(V+E). Поле `directed` позволяет всем алгоритмам использовать один тип. `inDegree` поддерживается при добавлении рёбер, и Kahn получает его копию, сохраняя исходный граф.

## 4. DSU: главные вопросы

DSU поддерживает разбиение вершин на непересекающиеся множества. `parent[x]` указывает на родителя, корень представляет множество. `makeSet(n)` создаёт n одиночных множеств. `components()` сначала равно n и уменьшается только после успешного объединения разных множеств.

`find(x)` сначала поднимается к корню, затем повторно проходит тот же путь и присоединяет посещённые вершины прямо к корню. Это **полное сжатие пути**, реализованное двумя циклами. `union(x,y)` находит корни, возвращает false при их совпадении и иначе присоединяет меньшее дерево к большему по `size`.

Пример: union(0,1) создаёт множество размера 2, union(2,3) — второе множество размера 2, union(1,3) объединяет их. Вершина 3 может иметь путь 3→2→0. После find(3) будет прямое parent[3]=0. Повторный union(0,3) ничего не объединяет и не уменьшает components.

**Почему нужны обе эвристики?** Объединение по размеру не даёт деревьям быстро становиться высокими. Сжатие пути ускоряет последующие поиски. Вместе они дают O(alpha(V)) амортизированно на операцию в последовательности, где alpha — обратная функция Аккермана. Это почти константа для практических размеров; формально она не равна O(1). Отдельный find в таком DSU может занять O(log V).

**Что измеряет dsuOps?** Число публичных find плюс число успешных union. Не число переходов по parent. Поэтому этот счётчик подтверждает количество DSU-вызовов в Kruskal, но сам по себе не доказывает alpha(V). Не выдавай число вызовов за фактическое число внутренних действий.

## 5. MST: Kruskal и Prim

MST соединяет все вершины связного **неориентированного** графа без циклов с минимальной суммой весов. В дереве V−1 ребро. Для несвязного графа получается MSF: одно дерево на каждую компоненту, всего V−C рёбер при C компонентах. Изолированная вершина считается компонентой с нулём выбранных рёбер.

### Kruskal

1. Отсортировать исходные рёбра по весу.
2. Взять очередное ребро u—v.
3. Если find(u) и find(v) различаются, объединить множества и добавить ребро.
4. Когда осталась одна компонента, можно прекратить просмотр; для несвязного графа просмотреть всё.

В проекте сортировка — собственный bottom-up merge sort с двумя массивами индексов рёбер. Сортировка стабильна: одинаковые веса сохраняют входной порядок. Сравнение весов увеличивает comparisons. union сам делает нужные два find, поэтому отдельные повторные find перед ним не нужны.

На connected.txt порядок начала такой: 1—2 (1), 0—2 (2), 3—4 (2), 0—1 (4), 1—3 (5). Первые три ребра берём, 0—1 отвергаем как цикл, 1—3 соединяет две оставшиеся компоненты. Получаем вес 1+2+2+5=10 и 4 ребра. Рассмотрели 5 рёбер, поэтому findCalls=10, successfulUnions=4, dsuOps=14.

Сложность: сортировка O(E log E), работа DSU O(E alpha(V)), инициализация O(V). Дополнительная память O(V+E). Ранняя остановка уменьшает просмотр и DSU-вызовы, но сортировка всех рёбер уже выполнена.

### Prim

Начинаем с вершины 0. Куча хранит кандидатов, которые соединяют посещённую часть с новой вершиной. Извлекаем минимальный вес; если вершина уже посещена, пропускаем запись. Иначе добавляем вершину и выбранное ребро, затем просматриваем её соседей. Когда куча опустела, текущая компонента закончена; начинаем со следующей непосещённой вершины.

Это **lazy Prim с кучей рёбер**. Старые записи могут оставаться в куче, поэтому проверка visited после remove обязательна. Self-loop не выбирается: его конец уже посещён. Параллельные рёбра разрешены, более выгодный кандидат может победить.

Точная оценка этой реализации для мультиграфа — O(V+E log(E+1)) времени и O(V+E) дополнительной памяти: куча может содержать O(E) записей. O(E log V) обычно относится к варианту с кучей вершин и decrease-key. Для E=4V и 20V обе логарифмические оценки эквивалентны по классу, но реализация всё равно разная.

### Почему оба алгоритма правильные?

Выучи **cut property**. Разрез делит вершины на две части; самое лёгкое ребро, пересекающее подходящий разрез, безопасно добавить к текущему лесу. Если его нет в некотором MST, добавление создаёт цикл. Из цикла можно удалить другое пересекающее разрез ребро не меньшего веса, сохранив связность и не увеличив сумму. Поэтому существует оптимальный остов, содержащий выбранное ребро.

В Kruskal разрез окружает одну DSU-компоненту. В Prim разрез отделяет посещённую часть от непосещённой. При одинаковых весах оптимальных деревьев может быть несколько: **веса обязаны совпасть, списки рёбер могут различаться**. Отрицательные веса для MST допустимы: здесь минимизируется вес дерева, а не кратчайшая прогулка с повторами.

## 6. SCC и Kosaraju

SCC — максимальное множество вершин, где каждая достижима из каждой по направлениям рёбер. Обычная компонента связности и SCC — разные понятия. Одиночная вершина всегда SCC, но deadlock означает либо SCC из нескольких вершин, либо одиночную вершину с self-loop.

Kosaraju делает:

1. DFS исходного графа: записывает вершины **при выходе**, в порядке завершения.
2. Строит transpose: разворачивает все рёбра.
3. Берёт вершины в обратном порядке завершения и запускает DFS transpose из ещё не помеченных. Каждый такой DFS — одна SCC.

Ключевой смысл finish order: для ребра между разными SCC исходного графа максимальное время завершения компоненты-начала больше максимального времени компоненты-конца. Поэтому выбранная следующей компонента на transpose не ведёт в ещё необработанную другую компоненту. После неё можно продолжать по оставшимся вершинам.

**Почему нельзя просто положить вершину в order при первом посещении?** Нужен postorder — момент после обработки исходящих рёбер. В явном стеке хранятся и вершина, и курсор следующей дуги. Когда курсор дошёл до -1, мы имитируем возврат рекурсивного вызова и записываем завершённую вершину. Простая очередь посещения этого не обеспечивает.

**Почему без рекурсии?** У пути из 100 000 вершин глубина DFS может достигать 100 000. Рекурсивные вызовы используют ограниченный стек JVM. Массив кадров в heap позволяет выдержать такую глубину. На тестовом пути maxDepth точно 100 000, StackOverflowError отсутствует.

Время O(V+E), память O(V+E) с учётом transpose. DFS сканирует E дуг в первом проходе и E во втором: edgeScans=2E. Построение transpose также занимает O(V+E) времени и включено в time_ms, но не входит в счётчик DFS-сканирований. Это явно указано в README и отчёте.

На cyclic.txt группы вершин: {0,1,2}, {3,4}, {5}, {6}. Их четыре. Числовые labels могут отличаться у разных корректных алгоритмов; сравнивать нужно разбиение, а не номер компоненты.

## 7. Kahn и топологическая сортировка

Топологический порядок — перестановка всех вершин, где для каждого u→v вершина u стоит раньше v. Такой порядок существует тогда и только тогда, когда directed граф ацикличен.

Kahn копирует inDegree и кладёт все вершины с нулевой входящей степенью в очередь. Когда вершину извлекают, уменьшают степени всех её исходящих соседей. Если степень соседа стала нулём, его добавляют в очередь. Если вышло меньше V вершин, остался цикл. Код выбрасывает понятную ошибку вместо выдачи частичного результата за полный порядок.

Инвариант: каждая вершина в очереди уже не имеет необработанных предшественников. В DAG всегда можно продолжить с какой-то нулевой степенью. Если после остановки остались вершины, у каждой есть оставшийся входящий предшественник; следуя по ним, в конечном графе обязательно попадём в цикл.

Валидация создаёт pos и проверяет pos[u]<pos[v] для каждого ребра. Дополнительно проверяются размер массива, диапазон вершин и отсутствие повторов, иначе один и тот же номер мог бы скрыть пропущенную вершину. Время O(V+E), память O(V). На DAG edgeScans=E. На циклическом графе до ошибки может быть просмотрено меньше E рёбер.

## 8. Кратчайшие пути в DAG

Сначала строим топологический порядок Kahn. Все вершины с inDegree=0 получают distance=0, остальные — INF. Это соответствует виртуальному super-source с нулевыми рёбрами ко всем источникам. Изолированные вершины тоже источники и получают 0. Нельзя присваивать 0 всем вершинам: тогда положительный путь мог бы ошибочно проиграть несуществующему нулевому старту в середине графа.

Для каждого u в топологическом порядке перебираем u→v и делаем relaxation:

```text
candidate = distance[u] + weight(u,v)
if candidate < distance[v]:
    distance[v] = candidate
    parent[v] = u
```

При обработке u все её предшественники уже обработаны, поэтому distance[u] окончательно. Одного прохода достаточно. Время Kahn плюс relaxation — O(V+E); дополнительная память O(V). Основной счётчик записывает E именно для relaxation; предварительный Kahn имеет отдельный Metrics, а его время входит в общий запуск.

### Почему отрицательные веса разрешены?

Потому что нет циклов и мы не возвращаемся в уже обработанную вершину. Индукция по топологическому порядку не использует неотрицательность веса. В общем графе может не быть топологического порядка, а достижимый отрицательный цикл позволяет неограниченно уменьшать стоимость прогулки. При отрицательных рёбрах **без отрицательных циклов** общий граф решается Bellman–Ford; нельзя утверждать, что отрицательные веса вообще запрещены за пределами DAG.

У Dijkstra другая предпосылка: вершина с текущим минимальным расстоянием фиксируется благодаря неотрицательности рёбер. Пример 0→1 (2), 0→2 (5), 2→1 (-10) ломает обычную идею окончательного выбора вершины 1 при расстоянии 2. Это при этом DAG, который корректно решается топологическим проходом с distance[1]=-5.

### Восстановление пути и пример

`parent[v]` хранит предшественника, через которого улучшилось расстояние. От целевой вершины идём по parent до -1 и переворачиваем список. Для dag.txt расстояния `[0,0,-2,-1,-7,-5,0]`:

```text
1 -> 2 (-2) -> 3 (+1) -> 4 (-6) -> 5 (+2)
Сумма весов пути к 5: -2 + 1 - 6 + 2 = -5.
Сумма расстояний всех вершин: -15.
```

Источник 0 не обязан принадлежать кратчайшему пути. Источники 1 и 6 также стартуют с нулём. Сумма расстояний в CSV — checksum всех distances, а не длина одного маршрута.

## 9. Счётчики, графики и правильные выводы

Достаточно показать ограниченный масштаб и объяснить изменения; не нужно подгонять данные под красивую горизонтальную линию. Формальное доказательство сложности и эксперимент — разные виды аргумента.

**Где алгоритм выигрывает?** На этих входах у Kruskal меньше сравнений весов, чем у lazy Prim. Например, на самом большом dense — около 39.42 млн против 79.21 млн. Это аргумент для конкретных реализаций и входов. Для плотной матрицы можно выбрать другой Prim за O(V²), а не делать универсальный вывод из одной машины.

## 10. Как обосновать тесты

Скажи, что ожидания получены независимым способом:

- DSU сравнивается с примитивным relabeling: при union переписываем метки всех элементов одного множества. Это медленно, но просто и независимо.
- Kruskal и Prim сравниваются на 100 случайных графах, плюс отдельно проверяются циклы, сумма весов, число рёбер и компоненты. На 40 маленьких графах оптимум найден перебором подмножеств, а связность — матрицей достижимости, без DSU.
- SCC: из каждой вершины запускается BFS по исходному и обратному графам. Две вершины в одной SCC, если взаимно достижимы. Сравниваем пары, а не произвольные IDs.
- DAG paths сравниваются со Bellman–Ford на 100 случайных DAG с отрицательными весами. Для каждого восстановленного пути проверяется старт в источнике, конец и сумма весов.
- Цикл и self-loop должны отвергаться Kahn; некорректная перестановка не должна проходить валидатор.
- Путь из 100000 вершин проверяет stack safety, замыкание его в цикл — большую SCC.
- Long arithmetic проверяет сумму, которая не помещается в int.
- Bonus longest path сравнивается с полным перебором путей на маленьких DAG-конденсациях.

Проверка двух похожих алгоритмов полезна, но они могли бы разделять ошибку. Именно поэтому добавлены независимые BFS, Bellman–Ford и полный перебор.

## 11. Бонусы

### Tarjan

Один DFS вместо двух. `index[v]` — номер открытия, `low[v]` — наименьший достижимый discovery index с учётом дерева DFS и связей с активной частью обхода. `onStack[v]` отличает активные вершины от уже завершённых SCC. Есть **два стека**: кадры обхода и активные вершины SCC.

Если сосед не посещён, спускаемся и при возврате обновляем low родителя через low ребёнка. Если сосед уже посещён и ещё активен, обновляем через **index соседа**, не произвольно через low. Если low[v]==index[v], вершина v — корень готовой SCC: снимаем активные вершины до v включительно. Рёбра в уже снятые компоненты не уменьшают low.

Kosaraju и Tarjan должны давать одно разбиение, но порядок IDs различается. Бенчмарк проверяет биекцию между метками за O(V). Tarjan scans=E, Kosaraju scans=2E; на большом dense это 2 млн и 4 млн. Tarjan также экономит память transpose, но его инварианты сложнее для объяснения.

### Конденсация и critical path

Сжимаем каждую SCC в одну вершину и сохраняем рёбра между разными SCC. Если бы в таком графе существовал цикл, его компоненты были бы взаимно достижимы и изначально принадлежали бы одной SCC. Значит, результат DAG.

Для максимального пути вместо min используем max в топологическом проходе. Веса межкомпонентных рёбер трактуются как задержки зависимостей; если рёбер между парой SCC несколько, сохраняется максимальный вес. Внутренние рёбра SCC удаляются. Поэтому этот результат не является длиной максимального простого пути исходного циклического графа и не вычисляет длительность работ внутри SCC.

Critical path в планировании — самая длинная цепочка зависимостей. При неотрицательных длительностях и достаточном числе исполнителей она задаёт минимально возможное время завершения. Для настоящего расписания циклическую зависимость внутри SCC сначала нужно устранить. На cyclic.txt critical path конденсации имеет длину 4.

Почему longest path простой здесь? В DAG нет циклов, и динамика по топологическому порядку рассматривает все зависимости за O(V+E). Longest simple path в общем directed графе NP-hard; если разрешить повторения по положительному циклу, максимум прогулки может вообще отсутствовать.

## 12. Выбор алгоритма: тренировка главного вопроса

| Вопрос преподавателя | Ответ с причиной |
| --- | --- |
| Даны дороги и стоимость, нужно соединить районы | MST: Kruskal или Prim, потому что минимизируется сумма выбранной сети. |
| Дана edge list, граф разреженный | Kruskal: уже есть список для сортировки, DSU быстро проверяет соединение компонент. |
| Дана adjacency list и сеть растёт от одной вершины | Prim естественно работает с frontier; сравню затраты кучи с сортировкой для Kruskal. |
| Очень плотный граф в adjacency matrix | Prim без heap за O(V²), если требуется выбрать наиболее подходящую реализацию. |
| Граф дорог несвязный | MSF; Prim перезапускается, Kruskal оставляет несколько компонент. |
| Нужно найти deadlock в задачах | SCC: группа размера больше 1 или self-loop; Kahn только сообщает о наличии цикла. |
| Нужно просто выдать порядок выполнения | Kahn; если вышло меньше V, порядок не существует. |
| Pipeline — DAG, некоторые стоимости отрицательны | Topological shortest paths: O(V+E), отрицательные веса разрешены. |
| Циклы возможны, веса неотрицательны | Dijkstra для shortest paths. |
| Циклы возможны и есть отрицательные веса | Bellman–Ford и проверка отрицательных циклов. |
| Нужно время окончания проекта | Longest path в DAG с корректно заданными длительностями задач/зависимостей. |

MST и shortest path решают разные задачи: MST минимизирует суммарный вес всей выбранной сети, shortest path — стоимость маршрута между источниками и вершиной. Дерево кратчайших путей не обязано иметь минимальную общую сумму рёбер.
